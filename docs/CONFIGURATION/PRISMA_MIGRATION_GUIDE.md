# Prisma Migration Guide for Multi-Database Setup
[⬆️ Back to Documentation Home](../DOCUMENTATION_INDEX.md) | [📁 Back to Configuration](./)

## Overview

This guide explains how to properly generate and apply Prisma migrations for the three database configurations in this project.

## 📁 **Project Structure**

```
prisma/
├── schema.prisma                    # Development schema (PostgreSQL)
├── schema.postgres.prisma           # Production PostgreSQL schema  
├── schema.sqlite.prisma             # SQLite schema
├── migrations/                      # Development migrations
├── migrations-postgres/             # PostgreSQL-specific migrations
└── migrations-sqlite/               # SQLite-specific migrations
```

## 🎯 **When to Generate New Migrations**

Generate new migrations when you:
- Add new models to any schema
- Add/remove/modify fields in existing models
- Change field types, constraints, or defaults
- Add/remove indexes or unique constraints
- Modify relationships between models

## 🔧 **Method 1: Using Prisma Migrate Diff (Recommended)**

This method generates database-specific SQL by comparing schema states.

### **Step 1: Create Baseline Schema**

For each schema you want to migrate, create a baseline version without your new changes:

```bash
# Create baseline schemas (without new fields)
cp prisma/schema.postgres.prisma baseline_postgres.prisma
cp prisma/schema.sqlite.prisma baseline_sqlite.prisma  
cp prisma/schema.prisma baseline_dev.prisma

# Remove your new fields from baseline schemas
# Edit each baseline file to remove the new fields you added
```

### **Step 2: Generate Migrations Using Diff**

```bash
# PostgreSQL Migration
npx prisma migrate diff \
  --from-schema-datamodel="baseline_postgres.prisma" \
  --to-schema-datamodel="prisma/schema.postgres.prisma" \
  --script > prisma/migrations-postgres/$(date +%Y%m%d%H%M%S)_your_migration_name/migration.sql

# SQLite Migration  
npx prisma migrate diff \
  --from-schema-datamodel="baseline_sqlite.prisma" \
  --to-schema-datamodel="prisma/schema.sqlite.prisma" \
  --script > prisma/migrations-sqlite/$(date +%Y%m%d%H%M%S)_your_migration_name/migration.sql

# Development Migration
npx prisma migrate diff \
  --from-schema-datamodel="baseline_dev.prisma" \
  --to-schema-datamodel="prisma/schema.prisma" \
  --script > prisma/migrations/$(date +%Y%m%d%H%M%S)_your_migration_name/migration.sql
```

### **Step 3: Clean Up**
```bash
# Remove baseline files
rm baseline_*.prisma
```

## 🚀 **Method 2: Using Prisma Migrate Dev (Alternative)**

This method uses Prisma's built-in migration generation.

### **Prerequisites**
- Ensure each migration directory has the correct `migration_lock.toml`
- Have access to a database for each type (for validation)

### **Generate Migrations**

```bash
# PostgreSQL Migration
npx prisma migrate dev --name your_migration_name --schema=prisma/schema.postgres.prisma --create-only

# SQLite Migration
npx prisma migrate dev --name your_migration_name --schema=prisma/schema.sqlite.prisma --create-only

# Development Migration  
npx prisma migrate dev --name your_migration_name --schema=prisma/schema.prisma --create-only
```

**Note**: The `--create-only` flag generates the migration file without applying it.

## 📋 **Migration Lock Files**

Each migration directory needs a `migration_lock.toml` file:

### **prisma/migrations-postgres/migration_lock.toml**
```toml
# Please do not edit this file manually
# It should be added in your version-control system (i.e. Git)
provider = "postgresql"
```

### **prisma/migrations-sqlite/migration_lock.toml**
```toml
# Please do not edit this file manually
# It should be added in your version-control system (e.g., Git)
provider = "sqlite"
```

### **prisma/migrations/migration_lock.toml**
```toml
# Please do not edit this file manually
# It should be added in your version-control system (i.e. Git)
provider = "postgresql"
```

## 🔄 **Applying Migrations**

### **To Development Database**
```bash
npx prisma migrate deploy --schema=prisma/schema.prisma
npx prisma generate --schema=prisma/schema.prisma
```

### **To PostgreSQL Production**
```bash
npx prisma migrate deploy --schema=prisma/schema.postgres.prisma
npx prisma generate --schema=prisma/schema.postgres.prisma
```

### **To SQLite Database**
```bash
npx prisma migrate deploy --schema=prisma/schema.sqlite.prisma
npx prisma generate --schema=prisma/schema.sqlite.prisma
```

## 🔍 **Verifying Migrations**

### **Check Migration Status**
```bash
# Development
npx prisma migrate status --schema=prisma/schema.prisma

# PostgreSQL
npx prisma migrate status --schema=prisma/schema.postgres.prisma

# SQLite
npx prisma migrate status --schema=prisma/schema.sqlite.prisma
```

### **View Generated SQL**
```bash
# View the latest migration for each database
cat prisma/migrations-postgres/[timestamp]_migration_name/migration.sql
cat prisma/migrations-sqlite/[timestamp]_migration_name/migration.sql  
cat prisma/migrations/[timestamp]_migration_name/migration.sql
```

## ⚠️ **Important Notes**

### **Database-Specific Differences**
- **PostgreSQL**: Uses simple `ALTER TABLE` statements
- **SQLite**: May use `RedefineTables` approach for complex changes
- **Development**: Follows PostgreSQL syntax (since it uses PostgreSQL)

### **Migration Naming**
- Use descriptive names: `add_user_preferences`, `update_group_types`, etc.
- Keep names consistent across all three migration directories
- Use timestamps for ordering: `YYYYMMDDHHMMSS_migration_name`

### **Schema Synchronization**
- Always update all three schema files simultaneously
- Ensure field definitions are identical across schemas
- Only the `provider` and connection details should differ

## 🛡️ **Safety Checklist**

Before applying migrations:

- [ ] **Backup your database**
- [ ] **Test migrations on a copy first**
- [ ] **Review generated SQL carefully**
- [ ] **Ensure all three schemas are in sync**
- [ ] **Verify migration lock files are correct**
- [ ] **Check that existing data won't be lost**

## 🔧 **Troubleshooting**

### **Migration Fails**
```bash
# Check what went wrong
npx prisma migrate status --schema=[schema_file]

# Reset migrations (development only)
npx prisma migrate reset --schema=[schema_file]
```

### **Schema Drift**
```bash
# Pull current database schema
npx prisma db pull --schema=[schema_file]

# Compare with your schema file
```

### **Lock File Issues**
```bash
# If provider mismatch, check migration_lock.toml
# Ensure it matches your database provider
```

## 📝 **Example Workflow**

1. **Modify schemas**: Update all three `.prisma` files
2. **Generate migrations**: Use Method 1 or 2 above
3. **Review SQL**: Check generated migration files
4. **Test locally**: Apply to development database first
5. **Deploy**: Apply to production databases
6. **Verify**: Check that changes are applied correctly
